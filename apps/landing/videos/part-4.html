Описание

Продолжаем серию «Строим настоящий Fullstack-проект с AI с нуля до продакшена».

В первой части мы создали основу проекта KaufmanBot на NestJS + Angular с Prisma, PostgreSQL, Docker Compose и другими инструментами.

Во второй части перешли к тестированию: создавали E2E, Unit и API-тесты с помощью LLM, разбирали подход с HeyAPI.

В третьей части настраивали CI/CD на GitHub Actions: пайплайны для бэкенда и фронтенда, линты, билды и юнит-тесты, MCP для GitHub и скилл для онбординга коммитов.

В этой части доводим до ума запуск продакшена: разбираем по шагам скрипт start:prod, ловим «database environment is not set», выясняем, почему PM2 работал без логов, и кладём собранный фронтенд внутрь бэкенда через ServerStatic. Потом настраиваем end-to-end тесты в GitHub Actions: workflow с ручным запуском, где можно выбрать ветку бэкенда и ветку фронтенда, поднять инфраструктуру с базой и MinIO, прогнать e2e и забрать отчёты в чек.

Отдельно показываю сам процесс работы с кодом, который генерирует AI: не пытаемся сделать всё сразу, а двигаемся постепенно — упали на environment, разобрались, починили, поехали дальше. Рутину отдаю дешёвой модели, решения принимаю сам и читаю то, что она написала. Два показательных случая: тест, который прошёл, но ничего не проверил, и упавший пайплайн, в который агент сходил сам через MCP для GitHub и починил его.

Также показываю, почему дома я работаю с дешёвыми моделями, а на работе с Claude, и сколько сгенерированного кода приходится перечитывать.

В видео:

  • Как устроен скрипт start:prod и чем он отличается от start:dev
  • Падение на environment и почему Node не должна сама читать env-файл
  • Логи PM2 в проде: причина в кластерном режиме и IPC
  • Фронтенд внутрь бэкенда через ServerStatic и флаг production
  • Два фронтенда дают рассинхрон: в дев-режиме статику глушим
  • Workflow с ручным запуском: ветка бэкенда и фронтенда на одном стенде
  • Playwright на фронтенде, JUnit-отчёты и разделение unit/e2e по папкам
  • Self-hosted раннеры и пересекающийся порт 3000
  • Тест-симуляция: прошёл, но ничего не проверил
  • Отладка упавшего пайплайна через MCP

Это четвёртая часть серии, в которой мы постепенно развиваем KaufmanBot и приближаем его к полноценному production-проекту.
